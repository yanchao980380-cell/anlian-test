# 评测 H5 标准底版 v1

2026-09-17 固化，基于用户认可的「双面之镜」页面。`source/` 是可运行的冻结参考，保留完整交互；`reference/home.png` 是首页视觉参照。现有 `sins/` 与该底版互不影响。

## 创建新评测

在仓库根目录运行（密码填写新评测实际密码）：

```powershell
node scripts/create-assessment.cjs --slug relationship --title "关系中的我" --password "123456"
```

密码支持 4–32 位英文字母或数字。脚本创建 `/relationship/`，替换页面标题、访问密码与历史键，并生成 `ASSESSMENT.md` 内容接入清单和 `theme.css`。已有目录不会覆盖，不自动增加合集入口。

这是**可运行的参考底版**，不是任意题库即插即用的通用评分引擎。新目录仍含七宗罪示例内容，完成下面的主题适配后才能作为新评测交付。参数中的标题只更新浏览器标题；可见首页标题需随主题设计，不能机械替换全部维度名。

## 固定流程

1. 主题首页：品牌导航、视觉主标题、简短价值说明、模式选择（按需）、报告收益、开始按钮、历史入口和娱乐说明。
2. 密码弹窗：遮罩、输入聚焦、错误反馈、Enter 确认、Esc 关闭、Tab 焦点循环。
3. 单题作答：选中反馈、自动进入下一题、上题回看、修改答案、进度。最后一题由用户确认提交。
4. 分析过渡与报告开启：保留顺畅过渡，文案匹配主题，不添加虚构收费、广告或关注要求。
5. 结果报告：一个明确主结论、解释依据、雷达图、优势与提醒、生活场景和可执行建议。
6. 收尾：历史报告恢复、下载文字、重测与返回当前评测首页。

首页不显示题数和合集入口。手机自然滚动，不用固定高度裁剪内容。顶部返回按钮只在离开首页后出现。

## 文件职责与内容适配

| 文件 | 职责 | 新主题需要调整 |
| --- | --- | --- |
| index.html | 页面、题库、评分、报告与历史逻辑 | 首页所有文案、维度、题目、画像、计分、图表、报告与模式 |
| full.css | 主题色、弹窗、选项、报告和无障碍补充 | 主题色、报告层次 |
| cover.css | 首页双卡封面布局 | 主题视觉与单/双模式布局 |
| framework.css | 品牌导航、容器、返回与视口适配 | 通常保留 |
| full.js | 自动答题、计时器清理、弹窗操作、同分说明、下载 | 新报告结构对应的选择器、同分规则、下载名称 |
| theme.css | 新评测最后加载的样式覆盖 | 优先在这里调整视觉 |

`index.html` 中定位 `dimensions`、`dimOrder`、`basicQuestions`、`vsQuestions`、`profiles`、`virtueProfiles`、`sinVirtuePair`、`calculate`、`renderBasicResultFromData`、`renderVsResultFromData`；这些属于示例的主题实现，不应原样套给其他主题。雷达轴数、标签、评分归一化与报告字段必须一起修改。

当前示例两种模式各 35 题。新评测题数由新需求决定，不继承此数量，也不默认要求七维或十四维。若只保留一种模式，移除另一种模式的入口与依赖，并检查历史恢复。

分数同分时，真实展示分数。主卡可选一项作为解读代表，但要解释同分与选择依据；不能人为给某一项加分。同分说明中的「参考版顺序」应改成新评测实际采用的规则。主结论、图表和解读必须使用同一份计算结果。

## 视觉约定

保留窄屏容器、顶部品牌、清晰大标题、主题卡片、单一主按钮、分段报告的层次。现有酒红与香槟是主题示例，不是所有新评测必须沿用的颜色。配图是可选项；图片不能影响文字可读性或导致水平溢出。新主题文案和设计需自行创作。

## 验收

- 320、375、430 和 1440 像素宽度下检查首页、弹窗、题目和报告；无横向溢出、按钮遮挡、卡片文字截断。
- 错误密码、正确密码、Enter、Esc、回看改答、快速点击、最后提交、重测与返回均正常。
- 所有模式走完整流程；雷达标签不重叠，分值与主结论一致。
- 检查极端答案、同分、不同答案组合，确保分数范围和建议对应正确。
- 不同评测历史隔离；重载后可恢复报告；评分结构变更时升级历史键版本。
- 下载文字报告包含当前主题、结论、雷达数据与建议；无示例主题残留。
- 浏览器无脚本错误；通过后才在根 `index.html` 添加新卡片。

可以参考 `tests/full35.browser.cjs` 的交互路径，但其中题数、模式、密码和报告选择器必须按新主题改写。底版生成器自身检查：`node --test tests/create-assessment.test.cjs`。

## 边界与版本

密码为静态前端入口校验，不是服务端鉴权；历史保存在当前浏览器 localStorage。底版未添加账号系统、支付或云端存储。

更新共用底版时，显式记录版本变更；重大结构改动另建 v2，避免覆盖用户已认可的 v1。后续可直接要求：「按评测标准底版做一个【主题】，题数【数量】，密码【密码】，希望结果包含【要求】」。
